# M12 ローカル脆弱性診断・ペネトレーションテスト

## 目的

本番相当のローカル成果物に対し、非破壊・低負荷の脆弱性診断とペネトレーションテストを実施し、再現可能な安全性検査と診断記録を残す。

## スコープ

- 配備ヘッダー、CSP、HTTPメソッド、パストラバーサル、配備ファイル露出。
- 履歴書入力と公開マニュアルのXSS・HTML注入耐性。
- JSON・JPEG境界、プロトタイプ汚染、ブラウザ保存領域、外向き通信。
- npm依存監査、秘密情報らしい文字列、危険API、ソースマップ、開発ファイルの配備混入。

## 非スコープ

- 公開XserverのTLS、HSTS、Apache実設定、ホスティングアカウント。
- DoS、負荷試験、大量リクエスト、第三者zipcloudへの診断。
- Git履歴の秘密情報検査と専用商用・外部スキャナーによる診断。
- 診断で見つかったアプリ本体の問題の自動修正。

## セキュリティに関する注記

- 対象は `127.0.0.1` の本番相当テストサーバーだけとし、外部通信はzipcloudリクエストをPlaywrightで模擬する。
- 個人情報を模した値はテスト専用文字列を使用し、実在する利用者情報を使用しない。
- 診断は非破壊・低負荷とし、ファイル破壊、権限取得、永続化、サービス妨害を行わない。

## 受け入れ条件

- XSS、パストラバーサル、プロトタイプ汚染、偽装JPEGが実行・露出・状態汚染を起こさない。
- PII模擬値がブラウザ保存領域やPWAキャッシュへ残らず、郵便番号以外を外部送信しない。
- 危険API、秘密情報らしい文字列、ソースマップ、開発ファイルが検査で検出されない。
- 開発依存込みと本番依存のみのnpm監査が既知の脆弱性0件を報告する。
- 診断対象外と残余リスクが診断レポートへ明記される。

## テストシナリオ

- `npm run test:security` で本番ビルド、配備検査、静的検査、ChromiumセキュリティE2Eを実行する。
- `npm run security:sca` で開発依存込みと本番依存のみの監査を実行する。
- `npm run check` でセキュリティ検査を含む通常品質ゲートを一括実行する。
- 診断結果は [セキュリティ診断レポート](../docs/SECURITY_ASSESSMENT_2026-07-16.md) に記録する。

## ロールバック時の注記

- セキュリティE2Eを外す場合もCSP・配備検査、依存監査手順、ブラウザストレージ境界テストは維持する。
- 検査の許可条件を緩和する場合は、脅威モデルと診断レポートを同時に更新する。
- 診断済みという記録だけを残して再現用テストを削除しない。
